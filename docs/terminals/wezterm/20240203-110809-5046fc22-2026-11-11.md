# WezTerm 20240203-110809-5046fc22 record (2026-11-11)

Result of the first checklist run for WezTerm.

This is WezTerm for Windows with its WSL domain (`WSL:Ubuntu-24.04`): the
window runs on Windows and lazarobox runs in WSL. The Linux build of WezTerm
was not run.

Keys were synthesized with Windows `keybd_event` into a dedicated WezTerm
window (as the Kitty record used xdotool), with a check before every key that
the window was in the foreground. The bytes each key reached the pane with
were logged by a raw-mode reader in a lazarobox pane; screens were read from
window screenshots; copies were read back with `Get-Clipboard`. To bring the
window to the front, the driver taps a lone `Alt`; each tap reached the pane as
an extra `00`, so those bytes are left out below (a rerun without the tap gave
exactly one `00` for the `Ctrl+Space` row).

## Known issues found by this record

- `Alt+Enter` is taken by WezTerm (fullscreen) and never reaches lazarobox,
  as in Windows Terminal. Terminal configuration, not a lazarobox fail: use
  `Ctrl+J` or disable the default assignment (see the checklist).
- `Ctrl+]` (`Ctrl+AltGr++` on the es layout) arrives as a plain `]`. Only
  matters where `Ctrl+Space` is swallowed, which is not the case here.
- A lone synthesized `Alt` tap reached the pane as `00`. Seen only with
  synthesized input; not checked with a physical keyboard.
