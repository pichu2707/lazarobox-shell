# tmux 3.5a record (2026-11-15)

Result of the first checklist run for tmux, as the terminal lazarobox runs in.

How this was run, so the results are read for what they are:

- The outer terminal is tmux itself. There is no GUI emulator around it: a private tmux server (`tmux -L lzr-record -f /dev/null`, so no `~/.tmux.conf` was read) ran lazarobox in a pane.
- Keys were synthesized with `tmux send-keys`, which writes to the pane and skips tmux's key tables and the outer terminal's encoding. Results were read with `capture-pane -p` (`-e` for colours) and from a raw byte reader (`stty raw -echo; dd | od`) in the lazarobox pane.
- Where a row depends on the key tables or on what a terminal sends, a second path was used: a headless client (a Python pty running `tmux attach`, `TERM=xterm-256color`) fed raw bytes, so tmux parsed them like a real terminal's input. This stood in for a terminal; a real emulator was not used, so rows that need one are `pending`.
- Options in effect: tmux defaults (`default-terminal tmux-256color`, `escape-time 10`, `extended-keys off`, `set-clipboard external`, `focus-events off`, `mouse off`, prefix `Ctrl+B`). Variants are named in the notes: `extended-keys on` / `always`, `set-clipboard on` / `off`, `allow-passthrough on`, `focus-events on`, `mouse on`, `terminal-features 'xterm*:RGB'`.

Also checked:

- The `CSI > 4 ; 0 m` modifyOtherKeys reset at startup and `CSI > 4 m` on exit are harmless: no text appears on screen, and `Ctrl+Space q y` exits with status 0 and no stray bytes in the pane.
- Inside the pane lazarobox sets `TERM=xterm-256color` for its own children (`TERM_PROGRAM` and `TMUX` are kept).

## Known issues found by this record

These are lazarobox issues to fix, not tmux fails, except where a row above says `fail`. None has an issue number yet.

- Copy under tmux's default `set-clipboard external` shows `(OSC 52 sent)`, but tmux drops it and nothing is copied. lazarobox could say that tmux needs `set -g set-clipboard on` when `TMUX` is set.
- When this record was made, the probe key was `tmux` for every outer terminal (`TERM_PROGRAM` wins), so a stored `pass` hid an outer emulator that swallows `Ctrl+Space`. Fixed in #785: inside tmux the key is now `tmux (<emulator>)` (for example `tmux (kitty)`), or plain `tmux` when no emulator is found. The rows above predate the fix; see [the terminals README](../README.md).
- `RECORDED_TERMINALS` in `src/core/desktop.rs` does not list `tmux` yet; see the README.
