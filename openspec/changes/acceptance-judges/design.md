# Design: Acceptance judges

Evidence marks: **[R]** read in code on `docs/acceptance-judges-proposal` a2be3bcd for this design; **[I]** inferred, to verify in the task that uses it. Decisions J1-J13 and J17 of `proposal.md` are binding (J17 amends J4, J10 and J11: the judges are the rows `judge-a` and `judge-b` of the `ODD + RDD roles` section, see D13). Specs read: `specs/acceptance-judges/spec.md` (written in parallel; the points where this design differs are listed in "Spec alignment").

## Technical Approach

A judge is one more kind of read-only reader in the S7b review (runtime/orchestra/review.rs), not a second system. Pure rules live in a new `src/core/ai/orchestra/judge.rs`: the level, the standard, the prompt, the verdict parser, the agreement rule and the changed-line ranges. `Review` (rdd.rs) keeps the judge record next to the lens findings, so the receipt, the correction bound and `conclude()` stay the same. A judge's failed criteria become ordinary `Finding`s (lens `Judge`, severe, caused, observed). That puts them in `blockers()`, so the existing single correction round covers lens blockers and failed criteria together (J12). The I/O stays where it already is: the host gate (runtime/tools/host/review.rs), the run manager (`conduct`, `correct`), the coordinator's `finish` and `next_turn`, and the app's key handlers.

## Spec alignment (for the spec author)

1. **Consent timing (J9).** "When the run starts" is read as the moment authorize grants `implement` (D10). That is the first point where read-only is known, and the first point where the ask can name the judge models. Runs with lifted gates ask at their first judged batch.
2. **Norms slice.** The spec tags the norms I/O [S4]. This design reads them in S3 (D3), so that two judge slices do not ship without norms. The pure cap stays in S1a.
3. **Verdict states.** `pass` with `unknown` criteria is allowed. The line then reads `pass · <m> criteria met, <u> unknown` (the spec shows only `<m> criteria met`). A criterion with no line at all is `inconsistent`.
4. **No-verdict reasons.** This design adds `unseen` to the spec's list.
5. **Level line.** It shows `size unknown` when classify did not close. The byte threshold is 16 KiB of staged text (D1).
6. **ASCII.** The spec's lines use `·` and `›`. The review lines already go through `say`. Whether the app sanitizes them to ASCII is [I], to check in S2a. The close wait line and the guidance hint use the spec's text unless that path is ASCII-only (guidance tests assert ASCII, guidance.rs:249 [R]); the hint falls back to `Enter finish anyway | Esc keep working`.
7. **Disagreement vs lens corrections.** Contested criteria are never corrected, but lens blockers in the same high review still are (D7).

Accepted risk (S3 norms I/O): races that swap a parent directory between the check and the open, and in-origin link targets such as `.env`, are guarded only by redaction of the norm text; `openat2` with `RESOLVE_BENEATH` is a possible later hardening.
