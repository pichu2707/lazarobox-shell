## PR1: core, fetch, cache (unreachable from the UI) - ~220 lines

Nothing here is called from a menu, planner or the Linker. Branch base: `main`.

- [x] 1.1 RED/GREEN: pure `pinned(id, pin)` and the pin constant. Files: `src/core/ai/mcp_secrets/lazarobox_client.rs` (new), `src/core/ai/mcp_secrets.rs` (module line). `pub const PROJECT_NUMBER: Option<&str> = None`. Test proves: id starting `<pin>-` with the `valid_id` shape is accepted; foreign number, a longer number that starts with the pin (`1234567890123-...` against `123456789012`), and pin `None` are refused; a `Some` constant is ASCII digits only (unit test on the constant). Spec: Integrity pin; design 2.
- [x] 1.2 RED/GREEN: `accept(status, body, pin)`. Same file. Test proves: 200 plus valid Desktop body returns the client; 301, 404 and other statuses map to `HTTP <code>` / `redirected (HTTP 3xx)`; a body over 16 KiB maps to `larger than 16 KiB` without parsing; `web` key, missing key, non-printable value, bad suffix and invalid JSON map to `not a Desktop client file`; foreign project maps to `not from the lazarobox project`; pin `None` returns the not-configured notice. Reuses the existing `read_client` parsing. Spec: Size and shape, Request shape (redirect is a failure).
- [x] 1.3 RED/GREEN: `client_json(id, secret)` canonical text and the notice builders (all six notices of the design table plus the `<why>` strings). Same file. Test proves: the rebuilt text fixes `auth_uri`, `token_uri` and `redirect_uris` to Google's, so a fetched JSON with a foreign `token_uri` is dropped from the output; the text round-trips through the existing client reader; no notice contains the secret or the body; each notice string equals the design table verbatim. Constants `CACHE_FILE = "lazarobox-google-client.json"`, `URL_PATH = "/lazarobox/google-client.json"`. Design 3, Notices.
- [x] 1.4 RED/GREEN: `Curl::google_client(path)`. File: `src/runtime/hf.rs` (and its tests module). Test proves, with a fake curl that records arguments (the existing `hf` test helpers), that the args equal design 4 exactly: `-q --silent --show-error --user-agent <ua> --proto =https --proto-redir =https --max-time 15 --connect-timeout 15 --max-filesize 16384 --header "Accept: application/json" --write-out "\n%{http_code}" -- https://www.javilazaro.es/lazarobox/google-client.json`, with no `-L`, no `--fail`, no cookie, header or data option carrying user data, and no token. A reply with no `Content-Length` is still capped (read stops at cap+8 bytes). Spec: Request shape (fixed command line, plain HTTP never).
- [x] 1.5 RED/GREEN: `Target.backup` becomes `Option<&'static str>` and the cache `Target`. Files: `src/runtime/secrets_write.rs`. Test proves: existing targets still back up exactly as before (characterization, existing tests pass unchanged); a `None` backup writes no `.bak` copy; the cache target is `{ file: CACHE_FILE, backup: None, max: CLIENT_MAX, keep_mode: false }`. Design 6.
- [x] 1.6 RED/GREEN: save the cache. Files: `src/runtime/secrets_write.rs`, `src/runtime/secrets_write/google.rs`. Test proves, in a temp config folder with the existing `SaveFs` fakes: result is a regular file mode 0600 holding the canonical text; `google-oauth-client.json`, `secrets.toml` and `config.toml` stay byte-identical with the same mode; a symlinked cache path, a 0644 or two-link existing cache is refused with a notice naming the problem and not the secret (`lazarobox client not saved: <refusal notice>`); a failure after the temp file exists leaves no temp or partial file; identical existing bytes skip the write (mtime unchanged). Spec: Cache file; mcp-secrets: Link writes only the cache.
- [x] 1.7 RED/GREEN: `read_client_with` takes a file name and the cache read-back with the pin. Files: `src/runtime/secrets_write/google.rs`, `src/core/ai/mcp_secrets/lazarobox_client.rs`. Test proves: valid pinned 0600 cache returns id and secret with no notice; foreign project is refused with a pin notice (no secret in it); 0644, symlink and hard link are refused with `lazarobox-google-client.json: mode must be 0600 (chmod 600 <path>)` or the symlink / hard-link notice; missing cache is `None`; the two files (own and cache) are never read as each other. Existing own-client read tests pass unchanged. Spec: mcp-secrets OAuth client file read back.
- [x] 1.8 RED/GREEN: `refresh(curl, pin, secrets) -> Fresh | Stale(notice) | Failed(notice)`. File: `src/runtime/google_client.rs` (new), `src/runtime.rs` (module line only). Test proves, with the local `serve` from `hf/tests.rs` plus `Curl::local` and a temp config folder: 200 with a pinned client writes the cache and returns `Fresh`; 301, foreign pin, oversize and bad JSON write nothing and a prior valid cache stays byte-identical, returning `Stale` with the fallback notice; failure with no cache returns `Failed` (fetch-failed or refused text); unreachable host and a missing `curl` (empty PATH, no other process started) give the curl/network notice; pin `None` runs no curl and returns the not-configured notice; a symlinked or 0644 cache is not used as fallback.
